# UX Decisions Log

Append-only журнал UX-рішень. Нічого не видаляється — тільки додається.
Формат: дата · рішення · обґрунтування · альтернативи що розглядались.

---

## Глобальні UX-правила

**2026-05 · Без слайдерів і range-інпутів**
Ніде на платформі — ні у фільтрах, ні в будь-яких інших формах.
Причина: незручно на тач-пристроях, неточний ввід.
Альтернатива: chips для діапазонів, два текстових інпути для ціни (від/до).

**2026-05 · Без dropdown і calendar picker для дат**
Текстовий інпут з пресетом формату `dd.mm.yyyy`.
Причина: нативні date picker-и різняться між браузерами, dropdowns — зайвий клік.

**2026-05 · Телефон не показується публічно**
Комунікація лише всередині платформи.
Причина: безпека і довіра користувачів, захист від спаму.

## Каталог без логіну

**2026-05 · Каталог і лістинги відкриті без авторизації**
Причина: мінімальний поріг входу, SEO, discovery-first платформа.

**2026-05 · Кошик — можна додавати без логіну**
Логін/реєстрація запитується тільки при переході до оформлення.
Причина: не переривати намір покупки раніше ніж потрібно.

**2026-05 · Swap і вішліст — клік тригерить логін**
Кнопки видимі для всіх, але дія вимагає акаунту.
Причина: показати цінність фічі до реєстрації.

## Топ-бар

**2026-05 · Трьохколонкова структура: лого | пошук | іконки**
Порядок іконок праворуч: нове оголошення → акаунт → кошик.
Причина: стандартна передбачувана структура маркетплейсу. Пошук по центру підкреслює discovery-first характер платформи.

**2026-05 · Іконка акаунту — правий верхній кут, попап з 3 сценаріями**
- Гість: signup форма
- Гість: login форма
- Авторизований: ім'я + прізвище + email + 4 посилання (профіль, замовлення, обміни, вішліст)
  Причина: компактно, не потребує окремої сторінки для входу.

**2026-05 · Нове оголошення — завжди видима іконка `+`**
Відмовились від hover-reveal.
Причина: hover не працює на тач-пристроях.
На мобайлі: FAB (floating action button) внизу праворуч.

**2026-05 · Пошук — завжди видимий у центрі хедера**
Відмовились від окремої іконки пошуку праворуч.
Причина: дублювання з центральним пошуком. На мобайлі — іконка що розгортає інпут.

## Каталог / Грід

**2026-05 · Іконки екшенів на картці — hover reveal на десктопі**
На мобайлі: іконка вішліста завжди видима у куті картки.
Причина: зберігає картку чистою, рослина залишається головним візуальним елементом.

**2026-05 · Sticky фільтр-іконка знизу → попап з 6 опціональними кроками**
Поля фільтру:
- Категорія → chips
- Стан рослини (2 варіанти) → toggle
- Діаметр горщика → chips (XS/S/M/L/XL), не слайдер
- Є обмін → toggle
- Ціна → два текстових інпути (від/до)
- Місто → text input з autocomplete
  Причина: мобайл-first патерн, не займає місце в основному лайауті.

**2026-05 · Quick View — відкладено після MVP**
Причина: зайва складність для MVP, логічний крок після підтвердження product-market fit.

## Сторінка деталей

**2026-05 · Кнопка ← Назад до каталогу замість breadcrumbs**
Причина: плоска структура каталогу не потребує breadcrumbs. Одна кнопка — чистіше, більш community-відчуття.

**2026-05 · Ліва колонка з фото — sticky до кінця правої колонки**
Нижче правої колонки — схожі оголошення.
На мобайлі: sticky вимкнено, фото вгорі, деталі нижче.
Причина: класичний product page патерн, фото залишається у фокусі поки юзер читає деталі.

**2026-05 · Sticky CTA бар знизу поверх контенту**
Містить: назву рослини + кнопку "Купити" + кнопку "Запропонувати обмін".
Причина: обидві основні дії завжди доступні без скролу вгору.

## Auth / Onboarding

**2026-05 · Sign up: посилання на Terms of Use під кнопкою**
Формат: `Реєструючись, ти погоджуєшся з [Умовами використання]`
Причина: юридичний мінімум і сигнал довіри.

**2026-05 · Login: посилання "Забули пароль?"**
Причина: обов'язковий елемент для email/password flow.

**2026-05 · Auth MVP: Google SSO + Apple SSO + опціональний email/password**
Фото профілю — обов'язкове. Email верифікація — відсутня (знижує friction).
TOS enforcement і 2FA — після MVP.
Причина: мінімальний поріг входу при достатньому рівні довіри.

**2026-05 · Єдина модель профілю (Shafa/Vinted патерн)**
Немає окремих акаунтів buyer/seller.
`account_type` поле зарезервоване в БД для майбутніх комерційних акаунтів.
Причина: спрощує onboarding, відповідає community-першій ідентичності платформи.

## Кошик

**2026-05 · Додавання в кошик → відкривається side drawer**
На мобайлі: bottom sheet.
Drawer легко закривається (клік поза або ×).
Містить: "Продовжити шопінг" + "Оформити".
Причина: швидкий preview без втрати контексту каталогу.

---

## Навігація / Футер

**2026-05 · Футер для інфо-посилань (About, Contact, Terms, Cookies, Privacy)**
Відмовились від: лівого сайдбару, окремої About-сторінки як навігаційного хабу.
Причина: лівий сайдбар займає цінне місце і виглядає як адмінка. Футер — universal pattern для маркетплейсів.

## Слоган / Брендинг

**2026-05 · Слоган "Створено для спільноти рослинарів" — під питанням**
Альтернативи що розглядались:
- "Місце, де рослини знаходять нових господарів"
- "Обмінюйся. Ділись. Ростеш разом."
- "Спільнота, яка ділиться зеленим"
  Причина перегляду: "Створено для" — пасивне формулювання, звучить як tagline компанії а не запрошення до спільноти.
  Статус: не затверджено, потребує рішення.
