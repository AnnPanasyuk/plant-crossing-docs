# Legal/Safety-модерація — TODO

**Статус:** не вирішено, обсяг не визначений. Потребує консультації з юристом перед публічним лончем.
**Дата фіксації:** 2026-07-09

---

## Проблема

`analyzePlant`/`checkForScam` (описані в `ai.md`) — це product-quality модерація: чи фото відповідає рослині, чи оголошення не скам/дублікат. Вони **не** заточені під виявлення заборонених категорій контенту (зброя, наркотики, насильство тощо) — модель ніколи не отримувала таке завдання в system prompt. Це дві різні відповідальності, які легко сплутати під одним словом "модерація".

**Контекст ризику:** PlantCrossing має мінімальний поріг входу (без email-верифікації, без телефону, без ToS enforcement у MVP) — сама архітектура, обрана заради UX, знижує bar для потенційних зловживань.

---

## Важливо

Це не юридична консультація — практичний фрейм для орієнтації, не заміна консультації з юристом.

---

## Практичний мінімум для розгляду

1. **Report/flag кнопка** на кожному оголошенні — community-driven виявлення, не покладається тільки на AI. Органічно лягає в community-first позиціонування продукту.
2. **Розширення system prompt `analyzePlant`** (або окрема функція) явно забороненою категорією контенту — додатковий `issues`-тип, дешево додати на вже існуючу інфраструктуру виклику Claude API.
3. **Notice-and-takedown механізм** — швидке видалення за скаргою. Для MVP: вручну через Drizzle Studio (той самий патерн, що вже є для manual review в `checkForScam`).
4. **ToS** — явна заборона нелегального контенту в Terms of Use, дає юридичну підставу для видалення й аргумент "ми попередили".

---

## Наступний крок

Одна коротка консультація з юристом (навіть неформальна) перед публічним запуском — щоб визначити реальний обсяг покриття (список заборонених категорій, вимоги щодо швидкості реагування на скарги, чи достатньо notice-and-takedown моделі для юрисдикції).
